
이 번 6주차 강의를 통해 객체 지향 설계의 핵심인 SOLID 원칙과 이를 구현하기 위한 기술적 메커니즘인 IoC(제어의 역전), DI(의존관계 주입)의 개념과 상호 연관성을 검토하였습니다.

SOLID 원칙 중 단일 책임 원칙(SRP)과 개방-폐쇄 원칙(OCP)은 코드의 변경 가능성을 최소화하고 확장성을 확보하는 기준이 됩니다.기존에 작성 하던 방식처럼 하나의 클래스가 다수의 역할을 수행하거나, 기능 추가 시 기존 소스 코드를 직접 수정해야 하는 구조는 유지보수 비용을 증가시킨다는 점을 확인했습니다. 특히 의존관계 역전 원칙(DIP)에 따라 클라이언트 코드가 구체 클래스가 아닌 인터페이스(추상화)에 의존해야만 결합도를 낮출 수 있음을 파악했습니다.

이러한 OOP 원칙을 실제 코드로 구현하는 과정에서 IoC와 DI의 필요성을 이해할 수 있었습니다. 객체의 생성 및 제어권을 개발자가 아닌 프레임워크(컨테이너)가 전담하는 IoC 개념을 통해, 컴포넌트 간의 강한 결합을 분리하는 구조적 기반이 마련됩니다.

실제 제어권의 역전이 일어나는 메커니즘인 DI는 외부에 존재하는 컨테이너가 런타임 시점에 필요한 의존 객체를 주입하는 방식으로 작동합니다. 수정자 주입이나 필드 주입 방식에 비해, 생성자 주입 방식이 객체의 불변성을 보장하고 누락된 의존성을 컴파일 시점에 잡아낼 수 있다는 점에서 가장 안정적인 대안임을 기술적으로 비교·분석할 수 있었습니다.

결론적으로 SOLID 원칙이라는 설계론적 지향점이 IoC 컨테이너와 DI라는 구체적인 프레임 워크 기능을 통해 실현된다는 맥락을 확인하엿습니다. 향후 개발 과정에서 발생할 수 있는 결합도 증가 문제를 방지하기 위해, 인스턴스의 직접 생성(new)을 지양하고 인터페이스를 기반으로 한 의존성 주입 구조를 일관되게 적용해야 할 필요성을 정의한 시간이었습니다.
